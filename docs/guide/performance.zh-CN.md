# 性能

Eitri 的编辑器是装在 GTK 窗口里的 Neovide 渲染器。这些数字拿它和原生 Neovide 比。在 sway 和 Mutter 上，用编辑器自己的表面时，打出的字母到达屏幕的时间比原生 Neovide 晚 0.02 到 0.46 ms。数字来自 0.3.0 发布前不久的开发构建，在一台 AMD 台式机上测得，某一行另有说明的除外；0.4.0 没有重测。

## 在编辑器里打字

打出的字母到达屏幕的时间，比原生 Neovide 晚多少（中位数）。

| 编辑器的绘制方式 | 比原生 Neovide 晚 |
|---|---|
| 它自己的表面（默认），在 sway 和 Mutter 上、60 和 165 Hz 下（[编辑器怎样到达屏幕](editor-presentation.zh-CN.md)） | 0.02 到 0.46 ms |
| GTK 的方式，GTK 4.24.1，真实的 165 Hz 周期 | 5.97 ms |
| GTK 的方式，GTK 4.22.5，真实的 165 Hz 周期 | 0.30 ms |
| GTK 的方式，GTK 4.24.1，GTK 的 60 Hz 回退时钟 | 约 16.5 ms |

X11、NVIDIA 的驱动和 `editor.presentation = "gtk"` 用的是 GTK 的方式，合成器拒绝编辑器自己的表面时也会回退到它。GTK 的开发分支（4.25.0，提交 c36202f6，2026-10-25）上同样有这个延迟。

## 滚动

在 165 Hz 的输出上按住 `j`，用 GTK 的方式绘制，使用原样的呈现反馈（GTK 4.24 此时用它的 60 Hz 回退时钟）：

| | 每秒有变化的帧数 | 第 99 百分位的帧间隔 |
|---|---|---|
| 原生 Neovide | 165.5 | 6.1 ms |
| Eitri，GTK 4.24.1 | 140.6 | 12.1 ms |
| Eitri，GTK 4.22.5 | 165.4 | 6.1 ms |

用编辑器自己的表面时，滚动不比 GTK 的方式差。

## agent 回复流式输出时

回复按默认每秒 5 次更新输出时，在编辑器里打字会变慢。在 WebKitGTK 2.54 上，一次按键的重绘中位数是 11.2 ms，GTK 4.22.5 上也一样；在 WebKitGTK 2.52 上约为 2.3 ms。

## 底部终端

终端比你的按键晚画一个输出帧。在 sway 上，60 Hz 的输出里回显在按键后约 18 ms 出现在屏幕上，165 Hz 时是 8.7 ms。在 60 Hz 下，别的终端是：

| 终端 | 按键后回显，中位数 |
|---|---|
| Ghostty | 17.3 ms |
| WezTerm | 16.7 ms |
| Zed 里的终端 | 18.3 ms |
| foot | 1.0 ms |
| kitty | 0.7 ms |
| alacritty | 0.7 ms |

GTK 4.24 每按一个键会对窗口提交两次，合成器要晚一个刷新周期才显示第二次。终端在 GTK 的帧时钟里绘制，编辑器不是。想要最低的延迟，就在编辑器里运行 Neovim 自己的 `:terminal`：在缓冲区里打字的中位数是 1.7 ms。

## 内存、闲置和启动

- 只开一个标签页的闲置窗口，面板在窗口里面时比原生 Neovide 多用 232 MiB；在合成器模式下（面板是一个单独的窗口，平铺式合成器上的默认方式）多用 245 MiB。目标是不超过 256 MiB。在一块 AMD Radeon RX 9070 上、用 0.3.0 之后的开发版本测得；换成与它同机的集成显卡，窗口多用 248 到 259 MiB。
- 第一个 Claude 标签页约多用 85 MiB，其中包括它的 sidecar（占 79 MiB）。之后每多一个标签页约多 63 MiB，其中约 55 MiB 是它自己的 sidecar。你安装的 `claude` 命令是你自己的程序，不算在这些数字里：闲置时每个会话约 109 MiB，回合进行时更多。
- 闲置的窗口不画帧，每分钟约用 13 ms 的 CPU。
- 启动用 260 ms，原生 Neovide 是 253 ms。

## 高刷新率下有负载

在一台 Intel 笔记本上，165 Hz、有其他工作让机器保持 17 到 28 % 繁忙时，编辑器每秒画 137 到 149 帧，而原生 Neovide 画 160 帧；繁忙度 34 % 时是 111 帧，出现过一帧 83.6 ms。这些数字来自 Eitri 0.2.0 的打字延迟修复之前，没有重测。

## 限制

- 编辑器自己的表面还没有在 NVIDIA 的驱动或 KWin 上试过，`"auto"` 让 NVIDIA 继续用 GTK 的方式。
- 滚动还没有用真实周期的呈现反馈测过。GTK 4.16 以下编辑器换一种方式绘制，那里和 `:terminal` 缓冲区里的打字延迟还没有测过。
- 如果你在回复期间打字时觉得卡，请在「Testing feedback」表单里告诉我们，并附上你的 GPU 和显示器刷新率。
