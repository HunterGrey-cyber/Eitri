1. INSTALL                                                      *eitri-install*

The plugin is a thin launcher: it starts `eitri panel` or `eitri page` and
tells it which nvim to attach to. Each window installs the glue it needs
when it attaches, so the plugin and the installed Eitri never have to match
versions.

Eitri ships the plugin with its packages and its tarball installer. With
lazy.nvim, point a spec at the directory.

Distribution packages (.deb, .rpm, AUR):
>lua
  { dir = "/usr/share/eitri/nvim/eitri.nvim" }
<
User install (the tarball installer puts it in `~/.local/share/eitri/eitri.nvim`,
or under `$XDG_DATA_HOME/eitri/eitri.nvim` when that is set):
>lua
  { dir = vim.fn.stdpath("data"):gsub("nvim$", "eitri") .. "/eitri.nvim" }
<
The same path written out: `~/.local/share/eitri/eitri.nvim`. It is not under
`eitri/nvim/`: that directory holds the private nvim versions `eitri setup`
manages.

Without a plugin manager, add the directory to 'runtimepath':
>vim
  set runtimepath+=/usr/share/eitri/nvim/eitri.nvim
<

2. COMMANDS                                                       *:EitriPanel*

:EitriPanel [dir]       Open Eitri's agent panel beside this nvim, or attach
                        the panel that is already open for this project.
                        [dir] is the project; the default is the current
                        working directory. If nvim has no server address yet,
                        one is started. A second :EitriPanel while the first
                        panel is still starting attaches to it or raises it;
                        it never opens a second window. From the nvim the
                        panel is already attached to, it only raises the
                        panel: drafts being edited here stay open.

                                                                  *:EitriOpen*
:EitriOpen [dir]        Move this nvim into an Eitri window (a takeover), and
                        give it back to this terminal when the window ends.
                        Needs nvim 0.12 or later: below that it prints one
                        line and nothing loads. [dir] is the project; the
                        default is nvim's own global working directory. The
                        nvim must show exactly one UI, this terminal, and not
                        be waiting for a key. If nvim has no server address
                        yet, one is started. The terminal shows "This nvim is
                        open in Eitri" while the window has it; <Enter> there
                        takes it back at once, and so does closing the window,
                        quitting Eitri, a logout, a crash, or another UI
                        attaching. Eitri never signals this nvim and never
                        quits it. `:qa` typed in the window quits nvim. It is
                        refused (with one line) when `editor.takeover` is off
                        in Eitri's init.lua, when this nvim is already open in
                        an Eitri window, and when no display is available.
                        See the guide page "Take over a terminal nvim".

                                                                *eitri.open()*
require("eitri").open({dir})

The Lua form of :EitriOpen; {dir} is optional.

                                                                  *:EitriSync*
:EitriSync              Show conflicts, scan problems, copied-back files and
                        exclusions for this remote project. Press <Enter> on
                        an action. Merge opens a diff against the read-only
                        server copy. Use :write in the laptop buffer to save
                        the merge. Eitri backs up each version it replaces.

require("eitri.remote").status() returns the current buffer's project sync
status for a statusline, or an empty string outside an attached project.

                                                                  *:EitriPage*
:EitriPage {id} [dir]   Open a plugin page beside this nvim, following its
                        buffer. Completion lists the available page ids.
                        [dir] defaults to the current working directory.
                        A server address is started when needed. Closing this
                        nvim closes its page windows; closing a page leaves
                        nvim running. In Eitri's own nvim, use the prefix and
                        the page's key instead.

                                                                *eitri.page()*
require("eitri").page({id}, {dir})

The Lua form of :EitriPage; {dir} is optional. An older Eitri that has no page
windows shows an update message and opens nothing.

If `eitri` cannot be run, or the panel refuses, the reason is shown as an
error message. Once the panel is up it writes its output to a log file of its
own (under `~/.local/state/eitri/companion/`), so it keeps running after this
nvim quits; if it fails later, the message names that log.

                                                                   *eitri-log*
A window's message fits on one line, so a narrow nvim never waits for <Enter>
after it: a long log path is named by its file, and a longer message is cut
and ends with "…". When a message was shortened, everything the window wrote
is kept, with the time, in `eitri.log` in nvim's log directory (see
|stdpath()|, "log"); its last 400 lines are kept.

3. SETUP                                                         *eitri-setup*

Calling setup is optional.                       *eitri-page_mappings*
>lua
  require("eitri").setup({
    cmd = "eitri",      -- the launcher to run
    mapping = "<leader>ep",  -- a normal-mode map for :EitriPanel; none by default
    page_mappings = {        -- normal-mode maps; empty by default
      ["<leader>em"] = "markdown",
    },
  })
<

4. NAVIGATORS                                                    *eitri.edge()*

require("eitri").edge({direction})

When the panel is attached, window-navigation plugins that work in nvim's
windows can hand a move off the edge to Eitri, which moves focus to the panel
(or to the neighbouring window of your window manager). {direction} is one of
"left", "down", "up", "right". Returns true when a panel took the move, false
when none is attached (nothing happens then).

In the nvim of an Eitri window itself, the same call hands the move to that
window's own tiling (the next module, or the neighbouring window). Any other
word than the four directions returns false and sends nothing. If both a panel
and a window are there, the panel is asked first.

edge() does not look at nvim's own windows. Call it only at nvim's edge.
Without a navigator plugin, move within nvim first and hand off only when the
window number did not change:
>lua
  vim.keymap.set("n", "<C-l>", function()
    local before = vim.fn.winnr()
    vim.cmd.wincmd("l")
    if vim.fn.winnr() == before then
      require("eitri").edge("right")
    end
  end)
<
For smart-splits.nvim, call it from the `at_edge` callback:
>lua
  require("smart-splits").setup({
    at_edge = function(ctx)
      if not require("eitri").edge(ctx.direction) then
        -- no panel attached: your own fallback, or nothing
      end
    end,
  })
<
vim-tmux-navigator needs nothing here: when nvim is not inside tmux, the panel
treats its TmuxNavigate maps as plain window moves.

                                                                  *eitri.run()*
require("eitri").run({word}, ...)

In the nvim of an Eitri window, runs one of the window's actions, as
`:Eitri {word} ...` does: `require("eitri").run("split", "right", "agent")`.
Up to six words of letters, digits and . _ : = < > # - (64 bytes each); a word
outside that is refused with an error message and nothing is sent. Returns
true when the line was sent, false in any other nvim (including a terminal
nvim that only has the panel attached) or when it could not be sent.

                                                        *eitri.edit_selection()*
require("eitri").edit_selection()

Asks Eitri to put the keys in the agent panel with your Visual selection
attached and `Edit the selection: ` in the message box. The nvim of an Eitri
window and a terminal nvim with a panel attached both have it in Visual mode as
`<leader>ae`, put in only where nothing of yours holds that key. Call this from
a key of your own instead:
>lua
  vim.keymap.set("x", "<leader>k", function()
    require("eitri").edit_selection()
  end, { desc = "Eitri: edit the selection" })
<
Visual mode is not left, so the selection goes with the message you type next.
Returns true when the ask was sent, false in an nvim with no Eitri window or
panel attached.

5. INSIDE TMUX                                                     *eitri-tmux*

Inside tmux nothing in nvim's environment changes, the navigator maps are left
alone, and your tmux setup keeps moving between panes as it does today. The
panel is its own window; a move that reaches no window of the window manager
raises nothing and says nothing.

smart-splits inside tmux calls its `at_edge` callback only when tmux has no
pane further that way, so |eitri.edge()| never takes a move tmux could make:
at tmux's own edge it moves to the neighbouring window of your window manager
(the panel, when it sits there). Leave `edge()` out of `at_edge` if a move
should stop at tmux's edge instead.

6. WINDOW MANAGER                                                    *eitri-wm*

Moves between the nvim terminal window and the panel use your window
manager. In `init.lua` (see the Eitri documentation):
>lua
  eitri.config.set("companion.wm", "auto")
<
Accepted values: "auto" (the default; detected from the session), "hyprland",
"sway", "niri", "gnome", and "none" (the panel never asks the window manager
to move focus). Any other value stops the panel at start-up, naming the key.

On GNOME the moves go through the Eitri GNOME Shell extension, which the
packages install and you enable: `gnome-extensions enable eitri@huntergrey.cn`,
then log in again. It moves focus only right after you press a key in the
panel or in its editor.

To start Neovide and the panel together, run `eitri split [DIR]` in a shell:
it starts Neovide with nvim on a private socket and attaches the panel to it.
The panel closes when that Neovide exits; closing the panel leaves Neovide.

7. HEALTH CHECK                                                *eitri-health*

:checkhealth eitri

Finds the configured cmd (or eitri on PATH), prints its version, and lists the
page ids returned by `eitri page --list`. It reports an older Eitri without
page support. The health module loads only when called. Opening a buffer
under a recorded remote root starts one sync watch for that project and
reports the editor's modified buffers to it.
